# Recursive Project Tree Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair forged epoch timestamps and add an automatic, immutable audit trail for every supported Guard invocation against an initialized responsibility tree.

**Architecture:** Keep the three node ledgers as the only authoritative protocol history. Add a Project-root `observability/events/` stream containing one immutable JSON event per Guard invocation, including refusals and detective commands; the event records timing, request identity, result digest, and the complete Guard result without changing node sequence or protocol projections.

**Tech Stack:** Python 3 standard library, JSON/JSONL, Markdown contracts, deterministic subprocess fixtures.

## Global Constraints

- The audit stream is non-authoritative and cannot approve, adjudicate, or reconstruct missing canonical ledger records.
- “Complete” means complete for supported Guard invocations after a Project root can be resolved; arbitrary shell, model, OS, and direct filesystem actions remain outside this boundary.
- Existing `docs/evaluations/` is user-owned and must remain untouched.
- Tests must fail for the missing behavior before Guard implementation changes.
- The three canonical ledger filenames and contiguous per-node `node_sequence` contract remain unchanged.
